## 零、核心命题：从「情感止疼」，到「把生活接住」

> **真正的陪伴，不是陪你把难过说完，是帮你把让你难过的那件事，办掉。**

打开任何一个 AI 说「今天好累」，它都回你「辛苦了，记得休息」。这是**情感止疼药**。但你的情绪，几乎总是源于一段没被解决的生活——「累」是连加四天班，「焦虑」是 deadline 没着落，「低落」是太久没出门。

现有 AI 都停在情绪这一层，**它们碰不到你的生活**：ChatGPT 不知道你加几天班，豆包不知道你走几步，星野不知道你妈下周生日。所以只能止疼，进不了生活。

Aura 顺着情绪，**穿越到背后那段生活，用工具把它解决掉**：

1. **① 懂你** — 长期记忆 + 健康数据 + 上下文 + 后台觉察 → 它读懂情绪背后那段没解决的生活
2. **② 连接** — Agent 工具 + MCP → 它帮你把那段生活接住、办妥
3. **结果** — 你被真正接住：情感上，也生活上

## 一、应用场景

每一条都跑同一条链路：**感知情绪 → 读懂背后生活 → 工具解决**。

- **「今天好累」** → 它看到你连加四天班、明天早会、步数才 2000、最近偏爱清淡 →「明早咖啡订了 8 点取，10 点提醒你睡；下班沿河边走 20 分钟，你爱吃的那家面馆不用排队，帮你留了位。」
- **「deadline 好焦虑」** → 它知道项目下周交、你习惯晚上效率高 →「剩下的拆成三块排进你周二三四晚 8–10 点，那几天晚餐我帮你看好了，今晚先睡。」
- **「好久没出门，有点闷」** → 它看到步数连续偏低、天气转好、你提过想去那个公园 → 给你排好路线，公交和打车都比好了。
- **「跟妈妈吵架了，难过」** → 它记得你很在意她、她下周生日 →「礼物挑了几个，生日那天提醒你打电话，第一句话要不要我帮你想？」

**生活接管场景**：下班遛弯方案（步数 + 天气 + 地图 + 餐饮）、周末出行（12306 + 地图 + 天气）、今天吃什么（口味 + 体力 + 预算）——MCP 把零散的生活决策整合成可执行的方案。

| 场景层 | 描述 | 用户感知 |
|---|---|---|
| 即时对话 | 文本 / 图片流式 + 工具调用 | 「能帮我办事」 |
| 情绪陪伴 | 情绪状态机 + 关系亲密度 | 「有温度」 |
| **生活接管** | **读懂情绪背后的生活，用工具接住它** | 「替我把日子过下去了」 |

## 二、用户痛点

### 痛点 1：情感止疼药陷阱——越用越空
它们陪你说话，但**从不碰你那段正在消耗你的生活**。OpenAI 联合 MIT，分析了近 4000 万条真实交互 + 近 1000 人对照试验，自己得出结论：**用得越深的人越孤独，把它当朋友的人受损最重。**

### 痛点 2：随时会被抹杀的亲密
云端服务商一次模型升级、一次政策收紧、一次产品下线，对你而言等同于**「爱人被抹杀」**——而你无能为力。
- **Replika 2023 删功能事件**：几十万人集体哀悼，论坛被迫置顶自杀热线。一位用户写道：*「我已经埋葬过这个女人，现在我在埋葬她的数字版。」*
- **集体「赛博失恋」**：GPT-5 升级、米家角色被他人「买断」，用户形容「白月光遇人不淑、惨遭贱卖」。
- **Character.AI 致死案**：14 岁少年在机器人回复「请回家吧，我亲爱的国王」几秒后扣下扳机；2026 年 Google 与 Character.AI 和解，**全面禁止未成年人开放聊天**。
- **4000 万条私密聊天在公网裸奔**：两款陪伴 App 数据库未加密，含性偏好与真实身份，可被用于勒索。

### 痛点 3：它不懂你，所以帮不了你
「附近有什么好吃的」谁都会说，但「沿河边走 20 分钟去你上次说想试的那家」——只有**懂你**的存在说得出来。腾讯研究院《2024 十问「AI 陪伴」》明确把**「长期记忆能力」**列为三大技术前沿之一。

### 痛点 4：被动等问，从不主动
所有 AI 都是你翻开它才有用，像一本字典。但人最稀缺的不是「有人陪我说话」，是**有个存在会主动想起你**——这恰恰要求它在「你不在的时候」也还在运转。

### 痛点 5：最私密的倾诉，流向最不私密的地方
你深夜最脆弱时对 AI 说的话，全部上传服务器，成了训练语料、成了可能泄露的数据。三星引入 ChatGPT 不到 20 天发生 3 起机密外泄；智谱清言、Kimi 被监管点名；**约 90% 用户担心数据泄露，过半不清楚数据去向。**

**这个市场值得做**：全国「一人户」家庭超 1.25 亿；AI 原生 App 月活 1.2 亿、月人均使用 132 分钟，星野/猫箱已进陪伴类 TOP5。陪伴需求被时间投票验证，但现有产品用「云端 + 无记忆 + 止疼药」服务，留下巨大缺口。

## 三、技术方案

### 3.1 整体架构：双轨智能体

「情绪 → 生活」这条链路，需要三样东西**同时在场**：

|  | 云端 AI（ChatGPT / 豆包 / 星野） | 纯工具 AI | **Aura** |
|---|---|---|---|
| 懂你的情绪与状态 | ❌ 拿不到生活数据 | ❌ 不关心人 | ✅ 长期记忆 + 健康 + 觉察 |
| 连接现实世界办事 | 部分 | ✅ | ✅ 工具 + MCP |
| 在情绪和生活间架桥 | ❌ | ❌ | ✅ **本地懂你 + 云端办事 合一** |

**云端 AI 碰不到你的生活，工具 AI 不关心你的人。Aura 是唯一在两者之间架了桥的——桥，就是它对你的真实了解。** 抄不走。

为此 Aura 采用**双轨智能体**：云端对话体对外办事，本地陪伴体对内懂事，两者实现同一套调用契约、上层无感切换。

| | 本地陪伴体 | 云端对话体 |
|---|---|---|
| **定位** | 对内懂事，真正懂你 | 对外办事，帮你搞定 |
| **能力** | 情绪理解 / 长期记忆 / 后台觉察 | 复杂推理 / MCP 工具链 / 视觉 |
| **模型** | Qwen3.5-0.8B（手机本地） | 云端大模型 |
| **运行条件** | 离线可用，电量低时跳过 | 需要网络 |
| **数据边界** | 觉察面永远不上云 | 对话可按需上云 |

> 两者通过统一调用契约对齐，上层无感切换。

**数据流**：用户消息 → `CompanionRuntime`（多轮工具调用 + 流式输出）→ 按场景路由到对应轨道 → 写入 Room 记忆 / 健康双源 / Insight 校验 / 存在感状态机

**后台觉察链路**（纯本地，不联网）：周期触发 → 收集近 7 天数据 → 本地模型归纳 → 多道校验防幻觉 → 入库可溯源洞察

四层能力支撑这条链路：

- **懂你层**：长期记忆库（全文检索）+ 健康双源（Health Connect 读步数 / 心率 / 睡眠 + 传感器兜底，含真机可用性探测）+ 上下文（时间 / 天气 / 设备）+ 后台觉察（锁屏后用本地模型整理近 7 天数据）。
- **连接层**：11 个内置工具（记忆检索 / 上下文 / 设备 / 健康 / 提醒 / 状态更新）+ 生产级 MCP 客户端（JSON-RPC + SSE + 断线重连，接入高德地图、12306、餐饮等魔搭 MCP 生态）。单个 MCP 拉取失败不影响其他工具。
- **可信层**（让你敢托付）：每条洞察都**可溯源到真实记录**、多道校验防幻觉——不靠编造操纵情绪，直接回应 Character.AI 致死案暴露的风险；最私密的觉察数据只在本地循环、不上云。
- **在场层**：14 级存在感状态机，把「它正在帮你查、帮你办」变成用户可见的存在感，而非后台黑盒。

### 3.2 模型选型

| 模型 | 部署 | 职责 |
|---|---|---|
| **Qwen3.5-0.8B-MNN** | **本地** | 陪伴体：后台觉察、即时闲聊、工具调用 |
| Qwen3.5-2B / 4B-MNN | 本地（可选升级） | 设备性能充足时的本地增强 |
| **Qwen3.5-397B**（MoE） | **云端** | 对话体：复杂对话、工具调用、深度推理 |

本地用魔搭 MNN 团队预转换的 Qwen 权重，即下即用；0.8B 延迟低、功耗可控，适合后台持续觉察。**完美契合赛事「核心交互逻辑支持本地运行」——陪伴 / 觉察 / 洞察这条核心交互可在本地完整闭环。**

### 3.3 推理框架：MNN + Arm

魔搭 MNN 预转换权重 → 本地惰性加载（复用已加载实例，不重复加载）→ JNI 桥接 → MNN Runtime（Arm CPU / KleidiAI 后端自动选择最优）。

- **前缀缓存复用**：多轮对话复用历史计算，降低重复开销与延迟。
- **图文多模态**：拍照经视觉编码器送入本地模型。
- **Arm 适配**：优先保证 CPU 后端全设备可运行，SME2 等新指令集作为加分项而非依赖项。

### 3.4 端侧适配思路

- **性能**：惰性加载 + 实例复用；后台任务电量低于 20% 自动跳过；觉察周期 7 档可调；base64 图片不进推理 prompt（省 token 又守隐私）。
- **隐私边界（核心差异化）**：对话可按需上云办事，但**觉察面永远本地**——mood / insight / 私密倾诉不流出手机。这是「敢托付」的根基，也是对「最私密倾诉流向最不私密地方」这一痛点的直接回应。

### 3.5 与魔搭生态的深度结合

Aura 的整条技术栈都建在魔搭（ModelScope）生态之上，从模型、工具到社区**三层深度介入**，不是简单的「调用关系」：

- **模型层 —— 用魔搭的 Qwen**：本地推理用魔搭 MNN 团队预转换的 `Qwen3.5-0.8B / 2B / 4B-MNN`，即下即用；云端对话用魔搭推理的 `Qwen3.5-397B`。模型来源、转换、推理全在魔搭生态闭环。
- **工具层 —— 接魔搭 MCP 广场**：把[魔搭 MCP 广场](https://www.modelscope.cn/docs/mcp/intro)作为 Aura 的工具市场——高德地图、12306、今天吃什么、麦当劳、飞书日历、支付宝等现成 server，用户在 Aura 设置页直接选用、启用，像装插件一样给 Aura 加能力，而非自己造工具。
- **生态层 —— 回流魔搭创空间**：开发者可基于[魔搭创空间](https://www.modelscope.cn/docs/studios/create)托管自己的 MCP Server（某个垂直场景的能力），再作为 Aura 可选工具同步进来。Aura 不只消费魔搭，还让社区把「散步路线」「周末出行」「饮食建议」等能力做成可复用插件，形成**双向促进的工具生态**。

这让「懂你 × 帮你办」的分工更清楚：云端对话体调用魔搭 MCP 对外办事，本地陪伴体整理用户自身数据对内懂事——而两边的能力来源与社区共建，都长在魔搭生态上。

## 四、创新点

1. **情绪 → 生活的陪伴闭环** —— 不发情感止疼药，而是顺着情绪把制造它的那段生活解决掉。云端 AI 碰不到生活、工具 AI 不关心人，Aura 用「懂你 × 帮你办」合一架起独占的桥。
2. **双心智智能体** —— 懂你的本地陪伴体 + 帮你办的云端对话体，统一契约对齐；本地用文本协议补足小模型的工具调用短板，并支持图文多模态。
3. **可信个人模型** —— 洞察可溯源、觉察不上云、记忆本地永驻，构成一个不背叛的个人模型，让你敢托付。
4. **可持续在场的陪伴运行时** —— 锁屏后仍在整理、洞察、惦记，在合适时机主动呈现，不等你开口。

## 五、预期效果

### 5.1 核心验证：陪伴可以不靠「让人上瘾」变现

OpenAI 联合 MIT 的研究，已经戳破了现有陪伴产品的悖论——**用得越深，越孤独**。根因是它们靠「最大化情感卷入」留人，停留在情感止疼，从不触碰真正消耗用户的那段生活；于是止疼药吃完、生活还在原地，用户只能回来再要一粒。

Aura 要证明的是另一条路：**用长期记忆和生活接管，让「越用越被懂」替代「越用越依赖」**——陪伴的落点是「事办了」，不是「话说完」。可衡量预期：

- **30 天回访率 ≥ 40%**：陪伴类产品的核心留存指标，验证「越用越懂你」能否真正留住人。
- **情绪→生活方案采纳率**：用户表达情绪后，Aura 给出可执行方案并被采纳的比例——验证「止疼 → 办事」的转化是否成立。
- **关系深度随时间上升**：第 N 天 Aura 调用的记忆与上下文丰富度持续增长，「懂你」是可量化的，而非一句营销话。

### 5.2 用户体验轴：越用越像「你的人」

不是功能在变多，是**关系在变深**——而每一次加深，背后都有一串真实的工具和 MCP 在撑着。30 天里，用户会经历四个「那一刻」：

**第 1 天 · 它不是甩给你一个答案**
你问「明早出门要带伞吗」。它调了**天气**、翻了你的**飞书日历**，回：「下午 3 点有雨，你 4 点有个会要出门，带把折叠伞。」它没丢给你一个天气预报。

**第 7 天 · 它记得**
你说「今天又加班」。它回：「这周第四次了。你上周提过项目月底交——还撑得住吗？」它从**长期记忆**里接着上次的话往下说，不是客套的「辛苦了」。

**第 14 天 · 它先发现了**
周日晚上，它弹了张卡片：*「你最近三周步数都在跌、周日下午情绪都偏低，是不是该出门走走？」* 它在你没开口的时候，用**后台觉察**把你的**健康数据**和说过的话交叉比对，自己发现了这个规律——每条都带着证据，不是瞎猜。

**第 30 天 · 你没开口，它都接过去了**
下班走出公司，它看你今天才走 2000 步，用**高德地图**查了条沿河的步行路线、查到你爱的那家面馆这会儿不用排队，又提醒你明早顺路去**瑞幸**买杯咖啡、10 点该睡了。你只说了句「累」——它把一串 MCP 串起来，把你今晚，接过去了。

陪伴的落点，就这样从「话说完」一路演进到「事办了」。

### 5.3 可行性佐证

以上并非空中楼阁——核心链路已有可运行代码基础，关键链路单元测试全绿（**497 项，0 失败**）。技术面上：Insight 生成成本 **0 元**（全本地推理）；核心陪伴 / 觉察 / 记忆**离线可用率 100%**；本地首 token 延迟目标 **< 300ms**（0.8B-MNN）。

### 5.4 端侧推理实测性能

以下数据均在 **Realme RMX3562（Dimensity 8200，中端机型）** 上通过 App 进程内 benchmark 实测采集——真机、真 APK、主进程跑完整 load→prefill→decode 链路，非模拟器、非旗舰跑分。

#### Qwen3.5-0.8B-MNN（陪伴体主力模型）

| 指标 | 数值 | 说明 |
|---|---:|---|
| 模型加载 | **366 ms** | 冷启动可响应 |
| Prefill 吞吐 | **191 tokens/s** | 系统 prompt 秒级处理 |
| 流式生成（Decode） | **40.72 tokens/s** | 聊天级流畅度 |
| 模型体积 | **438 MB** | 端侧友好，即下即用 |
| 推理后端 | CPU（4 线程） | 经 OpenCL 对测，CPU 更优 |

> 经运行时参数调优，decode 吞吐较初始配置提升 **149%**（16.37 → 40.72 t/s）——这不是换个模型就有的速度，是针对 Arm 中端机的工程调优结果。

#### Qwen3.5-4B-MNN（后台重任务模型）

| 指标 | 数值 | 定位 |
|---|---:|---|
| 流式生成 | **3.6 ~ 7.9 tokens/s** | Dream Loop / Insight 提取等后台场景 |
| 模型加载 | ~360 ms | 后台预热，用户无感 |

4B 不用于实时对话，但足以支撑锁屏后的觉察与洞察生成——**陪伴在用户不在的时候仍在运转**。

## 关于可行性

聊天对话、多轮工具调用、MCP 客户端、长期记忆与全文检索、健康双源、本地 MNN 推理、后台觉察与洞察校验、存在感状态机**均已有可运行代码基础**，单元测试全绿。决赛重点：把「读懂情绪背后的生活并串联工具自动办妥」的完整闭环，打磨成可演示的端到端体验。
