## 零、统一表述

### 0.1 项目一句话

Aura 是一款 Android AI 陪伴应用，主打“长期认识你”的陪伴体验：云端智能体负责对话与办事，本地陪伴体负责持续感知、记忆和主动关怀。

### 0.2 核心主线

- **陪伴**：不是只会聊天，而是能在合适的时机回应、沉默、安慰和跟进。
- **记忆**：不是临时上下文，而是可检索、可追溯、可长期积累的个人记忆。
- **洞察**：不是普通总结，而是基于本地数据生成可验证的 Pattern / Reminder / Connection Insight。
- **隐私**：对话可以按需上云，但 mood、insight、inner state 与 Auto Memory 保持本地。

### 0.3 对外统一口径

- 对外优先说 **“AI 陪伴 App”**，在需要强调差异化时再补 **“长期认识你的 AI”**。
- “第二大脑 / 数字孪生”作为增强解释，不作为第一句主定义。
- “双轨智能体”用于解释架构，不单独替代产品定位。
- 阶段描述统一使用“**当前已跑通的能力** + **下一阶段目标**”，避免 Phase / P1 / M0-M7 / v0.4 多套编号并存。

### 0.4 当前阶段描述

Aura 当前已经跑通文本聊天闭环、长期记忆、情绪与关系状态、Presence 状态控制、本地 LLM 链路、Reminder 与部分 Insight 雏形。接下来重点不是再堆概念，而是把“持续在场、主动洞察、可感知的陪伴”做成可展示、可验证、可复用的完整体验。

## 一、应用场景

### 1.1 核心场景：个人 AI 陪伴

Aura 面向**需要情绪支持、生活管理和长期个性化陪伴**的用户群体，目标不是做一个“会聊天的助手”，而是做一个会持续认识你、记住你、在合适时机主动关怀你的 AI 陪伴体。当前产品体验可概括为三层递进场景：

| 场景层 | 描述 | 用户感知 |
|---|---|---|
| **即时对话** | 文本/图片流式聊天，支持工具调用（天气/提醒/记忆搜索） | "Aura 能帮我办事" |
| **情绪陪伴** | 情绪状态机 + 关系亲密度模型 + Presence 状态动画 | "Aura 有温度" |
| **长期洞察** | Insight 系统：模式识别、重要日期提醒、关联发现、周报 | "Aura 越来越懂我" |

### 1.2 典型使用场景

**场景 A：日常对话与情绪感知**
用户下班后打开 Aura 说"今天好累"。Aura 通过情绪状态机感知到用户近几天情绪偏低，用克制的语气回应"最近几天好像都比较辛苦？"，而不是模板化的"辛苦了"。关系等级越高，回应越亲昵但不越界。

**场景 B：本地 Dream Loop — 锁屏后的"做梦"**
用户锁屏 5 分钟后，Aura 的本地 Qwen 自动启动 Dream Loop：整理今天 20 条对话 → 提取关键记忆 → 更新 Auto Memory 文件 → 在本地生成一条 Pattern Insight："你最近 3 周都周日下午情绪偏低"。**全程不联网、不上云、不花钱**。

**场景 C：视觉记忆与跨模态关联**
用户拍了一张夕阳照片发给 Aura，Aura 通过云端 Vision 理解图片内容并回应。同时，本地记忆系统记录"你在 2026-06-15 拍了张夕阳"。两周后，Connection Insight 触发："你上次拍夕阳是 6 月 1 号，好像每次拍完夕阳你第二天心情都不错？"

**场景 D：主动关怀（Pulse + Insight）**
周日晚上 9 点，Aura 的 Weekly Insight Worker 汇总本周数据，在主页展示一条卡片："这周你提到'deadline'5 次，但周五之后就没再提了——是搞定了还是暂时放下了？要不要聊聊？" 用户点击"和 Aura 聊聊"，进入对话。

**场景 E：下班后遛弯方案（Health + MCP + 本地生活）**
用户下班走出公司，Aura 发现他今天步数偏低、最近连续几天久坐，天气也适合出门，于是主动给出一个“下班后遛弯方案”：先沿着附近有树荫或水边的路线散步 20 分钟，中途经过一个适合停下来放空的夜景点，终点落在一家符合他口味偏好、适合一个人吃饭的小馆子。如果用户今天已经走了很多、情绪偏低或者天气闷热，Aura 也可以把方案调整成“少走一点，顺路买杯咖啡或简单吃点东西就回家”。这里地图、本地生活、咖啡与快餐服务都可以通过 MCP 接入，Aura 负责把它们整合成一条真正可执行的生活建议，而不是零散地回答“附近有什么”。

**场景 F：周末出行规划（12306 + 地图 + 天气）**
用户周五晚上突然想周末出门散散心，Aura 先根据他的出行时间、预算和天气情况，帮他查周边可达的高铁/火车班次，再结合地图 MCP 评估从家到车站、从到站到目的地的接驳方式。如果当天目的地天气不好，Aura 会自动换成更稳妥的城市内路线；如果有合适班次，它还能把“出发时间 + 到站后路线 + 目的地散步点 + 回程建议”串成一整套出行方案，让用户不是只看到一张车票，而是拿到一份完整的周末计划。

### 1.3 目标用户画像

- 独居 / 异地工作 / 社交圈较小的年轻开发者或知识工作者（18-35 岁）
- 重视隐私、不愿把生活数据全部交给云端 AI 的用户
- 对 AI 产品有好奇心、愿意长期"养成"一个 AI 的技术爱好者

## 二、用户痛点

### 2.1 现有 AI 陪伴产品的核心痛点

| 痛点 | 现有产品现状 | Aura 的解法 |
|---|---|---|
| **隐私焦虑** | ChatGPT / Replika / 星野等全部把对话上云，用户生活数据暴露给第三方 | 觉察面（mood/insight/内在独白）**永远只在本地 LLM 和本机存储循环**，隐私数据从不出手机 |
| **记忆断裂** | 每次对话从 0 开始，AI 不记得上周聊了什么；即使有 Memory 功能也是浅层 KV 缓存 | Room 持久化长期记忆 + Auto Memory 文件系统 + LLM reflection 决策记忆留存，**产品每天都在变值钱** |
| **被动响应** | 用户不说话 AI 就不动，只是一个"高级搜索引擎" | Dream Loop + Pulse + Insight：锁屏后做梦整理、定期主动推送洞察、重要日期提醒 |
| **千篇一律** | 所有用户得到相同的 AI 人格，无差异化陪伴 | 情绪状态机 × 关系亲密度 × Presence 状态系统，**随时间推移越来越像"你的人"** |
| **缺乏洞察** | 只回答问题，不会主动观察用户生活规律 | Insight 系统：模式识别（情绪周期）、关联发现（跨事件联系）、周报汇总 |
| **端侧能力弱** | 本地模型要么没有，要么只是"离线降级版" | 本地 LLM 承担**独立职能**（持续心跳/做梦/即时闲聊），不是云端的"低配替代" |

### 2.2 痛点验证：为什么现在是做这件事的时机

- **端侧算力成熟**：Qwen 0.8B-4B 量化后可在主流手机流畅运行，MNN + Arm SME2 进一步释放性能
- **隐私意识觉醒**：用户对"数据上云"越来越敏感，"数据留在本机"成为产品差异化
- **AI 陪伴需求真实**：Replika 等产品验证了市场存在，但都在云端红海竞争，**没有人认真做"端侧 + 长期记忆 + 洞察"这条路**

## 三、技术方案

### 3.1 整体架构：双轨智能体（Dual-Mind Architecture）

为实现“长期认识你的 AI 陪伴”这一产品目标，Aura 采用**双轨智能体架构**：云端对话体和本地陪伴体各司其职、互不干扰。

```
                          用户消息
                             │
                             ▼
                    ┌─────────────────┐
                    │  ChatViewModel  │  ← 路由决策入口
                    └────────┬────────┘
                             │
                ┌────────────┴────────────┐
                ▼                         ▼
      ┌──────────────────┐      ┌──────────────────┐
      │  对话体 (云端)    │      │  陪伴体 (本地)    │
      │                  │      │                  │
      │  Koog AIAgent    │      │  L3 Reactive     │ ← 即时响应
      │  + Tools         │      │   Coordinator    │
      │  + Vision        │      │                  │
      │  + Structured    │      │  L2 Dream        │ ← 锁屏触发
      │                  │      │   Pipeline       │
      │  Qwen3.5-4B/     │      │                  │
      │  Qwen3.6-Plus    │      │  L1 Heartbeat    │ ← 0.5 Hz
      │  (云端 API)      │      │   (KV-cache 续写)│
      │                  │      │  Qwen3.5-0.8B    │
      └────────┬─────────┘      └────────┬─────────┘
               │                         │
               │  ┌──────────────────────┘
               │  │
               ▼  ▼
        ┌──────────────────────┐
        │  Room / DataStore    │
        │  + Auto Memory 文件  │
        └──────────────────────┘
```

**关键设计原则**：
- **对话体（云端）**：对外办事 —— 工具调用、Vision、深度反思、长上下文
- **陪伴体（本地）**：对内懂事 —— 持续心跳、做梦整合、即时闲聊、Insight 提取
- **对话体永远不写 mood/relationship**（情绪画像是本地专属）
- **陪伴体永远不上云 inner_state/mood/insight 数据**（隐私数据不出手机）

### 3.2 Agent Tool Layer：让对话体能真正办事

Aura 的云端对话体不只是“会回复”，而是通过 Koog `ToolRegistry` 接入一组可观测、可记录、可开关的 Agent tools，让智能体能读取上下文、调用本地能力，并通过 MCP 扩展外部工具。

| 工具类别 | 已接入能力 | 作用 |
|---|---|---|
| **Memory** | `search_memory` / `search_records` / `search_summaries` | 检索长期记忆、原始记录和摘要 |
| **Context** | 当前时间、最近互动、用户上下文设置 | 让回复知道“现在”和“你是谁” |
| **Device** | 设备状态、天气 | 读取用户授权范围内的环境信息 |
| **Health** | Health Connect / 传感器健康数据查询 | 支持健康相关对话和 Insight 依据 |
| **Action** | 本地提醒创建 | 把对话转成真实系统动作 |
| **MCP** | 动态加载远程 MCP server tools | 扩展地图、本地生活、浏览器、外部服务和长期任务能力 |

工具层的设计重点是“可控”而不是“无限开放”：

- `CompanionToolRegistry` 统一注册内置工具，并只加载 enabled 且 ready 的 MCP server。
- 单个 MCP server 拉取工具失败不会影响其他 server 或内置工具。
- 工具调用会记录 started / succeeded / failed / validation failed 状态，供 UI、日志和调试链路使用。
- 图像输入或关闭工具时，Agent 使用空工具注册表，减少无关工具对模型推理的干扰。
- Dream Loop 这条本地觉察链路不接外部工具，避免把私密整理任务变成外部执行任务。

MCP 在 Aura 里的价值不只是“能接第三方工具”，而是把陪伴场景落到真实生活中。例如接入高德地图类 MCP 后，Aura 可以把当天步数、近期运动倾向、下班时间、天气、用户口味偏好和情绪状态结合起来，为用户生成一个真正可执行的“下班后遛弯方案”：

- 如果用户当天步数偏低、连续几天久坐，Aura 可以优先推荐一条 20-30 分钟的轻步行路线，而不是直接叫外卖。
- 路线中途可以串联一段有水边、日落视野、树荫或城市夜景的散步点，让“散心”而不只是“走路”。
- 终点可以落在一家符合用户偏好的餐厅，例如一个人也适合坐、口味清淡、离家不远、排队时间可接受的小馆子。
- 如果用户当天已经走得很多、天气太热或情绪低落，Aura 也可以改成“少走一点、找个安静地方坐一会儿、顺路吃点热乎的”的保守方案。
- 如果用户需要提神或想顺手买饮品，Aura 还可以结合瑞幸一类咖啡 MCP，把门店、优惠和路线合成一个“散步 + 买咖啡”的轻量方案。
- 如果用户只想低决策成本地解决晚饭，Aura 也可以结合麦当劳一类快餐 MCP，把“附近可去门店 + 当前活动/优惠 + 最短步行路径”拼成一个省心版本。
- 如果用户今天不知道吃什么，Aura 还可以接入“今天吃什么 / howtocook”一类 MCP，把天气、口味、是否想自己做饭、当前体力和预算结合起来，给出“做什么菜 / 买什么吃 / 去哪里吃”的轻量建议。
- 如果用户准备周末短途出行，Aura 还可以把 12306 一类出行 MCP 与地图、天气拼起来，从“查班次”扩展成“出发时间 + 接驳路线 + 到站后怎么走 + 回程建议”的完整计划。

也就是说，MCP 在 Aura 里不是孤立地回答“附近有什么”，而是把地图、本地生活、饮食和出行信息与用户自身状态拼成一条有节奏、有目的地、有情绪照顾的生活路线建议。

后续 Aura 还可以把魔搭（ModelScope）上的 MCP 生态作为工具市场来源之一，同步可用的 MCP server 供用户在设置页直接选择、启用和配置。例如地图、本地生活、咖啡、快餐、出行、支付、工作协同等 Hosted MCP 都可以作为备选能力来源，降低用户自己寻找和接入 MCP 的门槛，让“给 Aura 增加能力”这件事更像安装插件而不是做技术配置。

除了直接接入现成 MCP，Aura 还可以给用户和开发者留出“自己扩展能力”的入口：开发者可以基于魔搭创空间把自己的 MCP Server 托管出来，再把它作为 Aura 可选工具同步进来。这样，Aura 不只是消费现成的 MCP，还能让社区把“散步路线”“周末出行”“饮食建议”等能力做成可复用的插件，逐步形成 Aura 的工具生态。相关官方入口见：

### 3.3 模型选型

| 模型 | 规格 | 部署位置 | 职责 |
|---|---|---|---|
| **Qwen3.5-0.8B** (Q4 量化) | ~0.5 GB | **本地 / MNN** | 陪伴体：持续心跳（KV-cache 续写）、Dream Loop 摘要/分类、即时闲聊、mood drift、Insight 生成 |
| **Qwen3.5-2B/4B** (Q4 量化) | ~1.2-2.5 GB | **本地 / MNN**（可选升级） | 设备性能充足时的本地增强方案 |
| **Qwen3.5-4B** / **Qwen3.6-Plus** | 云端 API | **云端** | 对话体：主对话、工具调用、Vision、深度反思 |
| **Qwen3-VL-2B/4B** | 云端 API | **云端** | 视觉理解（拍照识物、食物热量、场景理解） |

**选型理由**：
- Qwen3.5-0.8B 在手机上推理延迟低（首 token < 300ms）、功耗可控，适合"持续运行"的陪伴体场景
- Qwen 系列中文能力强，适合情感细腻的陪伴对话
- 云端 Qwen3.6-Plus 保证复杂任务的回复质量
- 比赛要求"核心交互逻辑支持本地运行"，0.8B 陪伴体 + 4B 云端对话体的组合完美契合

### 3.4 推理框架：MNN + Arm SME2

```
Qwen 模型（HuggingFace 原始权重）
    ↓ 模型转换
MNN 格式（.mnn，支持 Q4/Q5/Q8 量化）
    ↓ 加载
MNN Runtime (libMNN.so, Android NDK)
    ↓ 推理后端
Arm CPU / KleidiAI / SME2（自动选择最优后端）
    ↓ 接口层
NativeMnnLlmBridge.kt (JNI)
    ↓ Kotlin 层
MnnLocalQwenEngine → LocalQwenExecutor
```

**MNN 选型理由**：
- 阿里自研推理引擎，与 Qwen 模型天然兼容，已有 `taobao-mnn/Qwen3.5-2B-MNN` 等现成模型
- 深度适配 Arm SME2 指令集，矩阵计算加速显著
- Android 核心 SO ~800KB，APK 体积影响小
- 支持 KV-cache 续写（Aura 陪伴体心跳的核心机制）

**SME2 适配思路**：
- 运行时检测 SME2 支持（`getauxval(AT_HWCAP2) & HWCAP2_SME2`）
- 有 SME2 的设备（如 MediaTek Dimensity 9500）自动启用 SME2 加速后端
- 无 SME2 的设备回退到普通 CPU / OpenCL / Vulkan 后端
- 比赛统一配发设备可确保 SME2 测试环境一致性

### 3.5 端侧适配方案

#### 3.5.1 性能策略

| 策略 | 实现 |
|---|---|
| **心跳节能** | L1 心跳 0.5 Hz，但 85% tick 为 no-op，实际生成约 0.05-0.1 Hz |
| **KV-cache 续写** | 模型状态持久化到文件，每次从上次中断处继续生成 ~30 tokens，避免每次从零开始 |
| **Dream Loop 条件触发** | 锁屏 > 5 分钟 / 充电中 / 累积消息 ≥ 10 条 / 距上次 > 6 小时 |
| **电量保护** | 电量 < 20% 不跑 Dream Loop；用户可调频率（节能/标准/高频） |
| **模型预加载** | App 启动时 `executor.preload()`，减少首次推理延迟 |
| **KV-cache 存储上限** | 单 cache 文件 ≤ 50MB，超限自动 reset；24h 自动 reset 避免偏题 |

### 3.6 Insight 生成流水线

Insight 是 Aura 的**核心差异化产品能力**，由本地 LLM 在闲时自动生成：

```
触发器（DreamLoopWorker / AnniversaryScanner / 周期触发）
    ↓
Stage 1: 数据收集（纯 SQL，不调 LLM）
    ↓
Stage 2: 本地 Qwen 归纳（maxTokens=300, temperature=0.3）
    ↓
Stage 3: Insight 提取 + 校验（必须有来源线索，confidence < 0.6 丢弃）
    ↓
Stage 4: 限流调度（同类别周上限，不在深夜推送）
    ↓
Stage 5: 呈现（主页卡片 / 聊天页 / 通知三路）
```

**三类 Insight**：

| 类型 | 频率 | 示例 |
|---|---|---|
| **Pattern**（模式识别） | 每周 ≤ 1 条 | "你过去 3 周都周日下午情绪偏低" |
| **Reminder**（重要日期） | 每周 ≤ 1 条 | "你之前提过妈妈下个月生日，要不要帮你查餐厅？" |
| **Connection**（关联发现） | 每月 ≤ 1 条 | "你上次拍夕阳和今天拍的刚好间隔两周，好像每次拍完你第二天心情都不错？" |

## 四、创新点

Aura 的创新不是“把模型搬到手机上”，而是把本地模型放进智能体分工里：云端智能体负责对外办事，本地陪伴体负责对内懂事，在手机里形成一个持续、私密、可验证的陪伴运行时。

### 4.1 双心智智能体：云端办事，本地懂事

Aura 不是在“云端模型”和“本地模型”之间做简单切换，而是把两条路径组织成两种智能体职责：云端对话体负责对外办事，本地陪伴体负责对内理解用户。

- 云端对话体走 Koog AIAgent，负责复杂对话、工具调用、Vision、MCP 和外部信息接入。
- 本地路径封装为 `ReactiveCompanion`，与云端 wrapper 对齐 `run / runStreaming / runStructured / runEvents` 契约。
- 云端这条路径还有一层可观测、可扩展、可关闭的 Agent Tool Layer：内置工具负责记忆、上下文、设备、健康和提醒，MCP 负责地图、饮食、出行等外部服务扩展。
- 这让 Aura 可以在同一套 UI 和 runtime 下，把“帮我办事”和“理解我”拆成两种智能体角色，而不是做成一个职责混杂的聊天机器人。

### 4.2 可持续在场的陪伴运行时：Dream Loop + Presence

本地模型在 Aura 里不是离线兜底，而是陪伴运行时的一部分：它在用户不说话的时候仍然能整理状态、等待时机、再回到用户身边。

- 情绪、关系、Presence、记忆整理和 Insight 生成都围绕本地状态展开。
- 后台 `DreamLoopWorker` 使用本地 Qwen 跑 pattern detect，不依赖用户实时输入。
- Dream Loop 这条后台觉察链路不调用外部工具，重点是整理“关于用户自己的信息”，而不是对外执行任务。
- `DreamLoopScheduler` 负责周期调度和立即触发，默认可按用户设置调整频率。
- `DreamDataCollector` 收集最近 7 天数据，渲染为本地模型可读的上下文。
- `LocalQwenExecutor` 调用本地 Qwen 输出结构化 Insight draft。
- `PresenceController` 与 `PresenceReactionPolicy` 把 streaming、搜索记忆、错误恢复等状态转成用户可感知的存在感，而不是只在后台跑一个黑盒任务。

### 4.3 可信个人模型：记忆、洞察与边界

Aura 不是只“记住用户说过什么”，而是把记忆、情绪、视觉证据和 Insight 组织成一个可验证、可修正、可拒绝的个人模型。

- Memory 保留 importance / confidence / source 等字段，不是单纯聊天日志。
- 没有来源线索的 Insight 直接丢弃。
- 来源线索至少 50% 必须能在 messages / memories / mood_snapshots 中真实查到。
- confidence 低于 0.6 的结果不入库。
- 近 30 天重复 heading 会被去重。
- 用户可以 dismiss、archive、mute category，也可以查看来源线索。
- 这让 Aura 的主动关怀不是黑盒猜测，而是可信、可修正、可控制的 Agent 输出。
