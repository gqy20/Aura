## 一、应用场景

### 1.1 核心场景：个人 AI 陪伴 + 第二大脑

Aura 面向**需要情绪支持、生活管理和长期个性化陪伴**的用户群体，提供三层递进场景：

| 场景层 | 描述 | 用户感知 |
|---|---|---|
| **即时对话** | 文本/图片流式聊天，支持工具调用（天气/提醒/记忆搜索） | "Aura 能帮我办事" |
| **情绪陪伴** | 情绪状态机 + 关系亲密度模型 + Presence 状态动画 | "Aura 有温度" |
| **长期洞察** | Insight 系统：模式识别、重要日期提醒、关联发现、周报 | "Aura 越来越懂我" |

### 1.2 典型使用场景

**场景 A：日常对话与情绪感知**
用户下班后打开 Aura 说"今天好累"。Aura 通过情绪状态机感知到用户近几天情绪偏低，用克制的语气回应"最近几天好像都比较辛苦？"，而不是模板化的"辛苦了"。关系等级越高，回应越亲昵但不越界。

**场景 B：本地 Dream Loop — 锁屏后的"做梦"**
用户锁屏 5 分钟后，Aura 的本地 Qwen 自动启动 Dream Loop：整理今天 20 条对话 → 提取关键记忆 → 更新 Auto Memory 文件 → 在本地生成一条 Pattern Insight："你最近 3 周都周日下午情绪偏低"。**全程不联网、不上云、不花钱**。

**场景 C：视觉记忆与跨模态关联**
用户拍了一张夕阳照片发给 Aura，Aura 通过云端 Vision 理解图片内容并回应。同时，本地记忆系统记录"你在 2026-06-15 拍了张夕阳"。两周后，Connection Insight 触发："你上次拍夕阳是 6 月 1 号，好像每次拍完夕阳你第二天心情都不错？"

**场景 D：主动关怀（Pulse + Insight）**
周日晚上 9 点，Aura 的 Weekly Insight Worker 汇总本周数据，在主页展示一条卡片："这周你提到'deadline'5 次，但周五之后就没再提了——是搞定了还是暂时放下了？要不要聊聊？" 用户点击"和 Aura 聊聊"，进入对话。

### 1.3 目标用户画像

- 独居 / 异地工作 / 社交圈较小的年轻开发者或知识工作者（18-35 岁）
- 重视隐私、不愿把生活数据全部交给云端 AI 的用户
- 对 AI 产品有好奇心、愿意长期"养成"一个 AI 的技术爱好者

## 二、用户痛点

### 2.1 现有 AI 陪伴产品的核心痛点

| 痛点 | 现有产品现状 | Aura 的解法 |
|---|---|---|
| **隐私焦虑** | ChatGPT / Replika / 星野等全部把对话上云，用户生活数据暴露给第三方 | 觉察面（mood/insight/内在独白）**永远只在本地 LLM 和本机存储循环**，隐私数据从不出手机 |
| **记忆断裂** | 每次对话从 0 开始，AI 不记得上周聊了什么；即使有 Memory 功能也是浅层 KV 缓存 | Room 持久化长期记忆 + Auto Memory 文件系统 + LLM reflection 决策记忆留存，**产品每天都在变值钱** |
| **被动响应** | 用户不说话 AI 就不动，只是一个"高级搜索引擎" | Dream Loop + Pulse + Insight：锁屏后做梦整理、定期主动推送洞察、重要日期提醒 |
| **千篇一律** | 所有用户得到相同的 AI 人格，无差异化陪伴 | 情绪状态机 × 关系亲密度 × Presence 状态系统，**随时间推移越来越像"你的人"** |
| **缺乏洞察** | 只回答问题，不会主动观察用户生活规律 | Insight 系统：模式识别（情绪周期）、关联发现（跨事件联系）、周报汇总 |
| **端侧能力弱** | 本地模型要么没有，要么只是"离线降级版" | 本地 LLM 承担**独立职能**（持续心跳/做梦/即时闲聊），不是云端的"低配替代" |

### 2.2 痛点验证：为什么现在是做这件事的时机

- **端侧算力成熟**：Qwen 0.8B-4B 量化后可在主流手机流畅运行，MNN + Arm SME2 进一步释放性能
- **隐私意识觉醒**：用户对"数据上云"越来越敏感，"数据留在本机"成为产品差异化
- **AI 陪伴需求真实**：Replika 等产品验证了市场存在，但都在云端红海竞争，**没有人认真做"端侧 + 长期记忆 + 洞察"这条路**

## 三、技术方案

### 3.1 整体架构：双轨智能体（Dual-Mind Architecture）

Aura 的核心技术创新是**双轨智能体架构** —— 云端对话体和本地陪伴体各司其职、互不干扰：

```
                          用户消息
                             │
                             ▼
                    ┌─────────────────┐
                    │  ChatViewModel  │  ← 路由决策入口
                    └────────┬────────┘
                             │
                ┌────────────┴────────────┐
                ▼                         ▼
      ┌──────────────────┐      ┌──────────────────┐
      │  对话体 (云端)    │      │  陪伴体 (本地)    │
      │                  │      │                  │
      │  Koog AIAgent    │      │  L3 Reactive     │ ← 即时响应
      │  + Tools         │      │   Coordinator    │
      │  + Vision        │      │                  │
      │  + Structured    │      │  L2 Dream        │ ← 锁屏触发
      │                  │      │   Pipeline       │
      │  Qwen3.5-4B/     │      │                  │
      │  Qwen3.6-Plus    │      │  L1 Heartbeat    │ ← 0.5 Hz
      │  (云端 API)      │      │   (KV-cache 续写)│
      │                  │      │  Qwen3.5-0.8B    │
      └────────┬─────────┘      └────────┬─────────┘
               │                         │
               │  ┌──────────────────────┘
               │  │
               ▼  ▼
        ┌──────────────────────┐
        │  Room / DataStore    │
        │  + Auto Memory 文件  │
        └──────────────────────┘
```

**关键设计原则**：
- **对话体（云端）**：对外办事 —— 工具调用、Vision、深度反思、长上下文
- **陪伴体（本地）**：对内懂事 —— 持续心跳、做梦整合、即时闲聊、Insight 提取
- **对话体永远不写 mood/relationship**（情绪画像是本地专属）
- **陪伴体永远不上云 inner_state/mood/insight 数据**（隐私数据不出手机）

### 3.2 模型选型

| 模型 | 规格 | 部署位置 | 职责 |
|---|---|---|---|
| **Qwen3.5-0.8B** (Q4 量化) | ~0.5 GB | **本地 / MNN** | 陪伴体：持续心跳（KV-cache 续写）、Dream Loop 摘要/分类、即时闲聊、mood drift、Insight 生成 |
| **Qwen3.5-2B/4B** (Q4 量化) | ~1.2-2.5 GB | **本地 / MNN**（可选升级） | 设备性能充足时的本地增强方案 |
| **Qwen3.5-4B** / **Qwen3.6-Plus** | 云端 API | **云端** | 对话体：主对话、工具调用、Vision、深度反思 |
| **Qwen3-VL-2B/4B** | 云端 API | **云端** | 视觉理解（拍照识物、食物热量、场景理解） |

**选型理由**：
- Qwen3.5-0.8B 在手机上推理延迟低（首 token < 300ms）、功耗可控，适合"持续运行"的陪伴体场景
- Qwen 系列中文能力强，适合情感细腻的陪伴对话
- 云端 Qwen3.6-Plus 保证复杂任务的回复质量
- 比赛要求"核心交互逻辑支持本地运行"，0.8B 陪伴体 + 4B 云端对话体的组合完美契合

### 3.3 推理框架：MNN + Arm SME2

```
Qwen 模型（HuggingFace 原始权重）
    ↓ 模型转换
MNN 格式（.mnn，支持 Q4/Q5/Q8 量化）
    ↓ 加载
MNN Runtime (libMNN.so, Android NDK)
    ↓ 推理后端
Arm CPU / KleidiAI / SME2（自动选择最优后端）
    ↓ 接口层
NativeMnnLlmBridge.kt (JNI)
    ↓ Kotlin 层
MnnLocalQwenEngine → LocalQwenExecutor
```

**MNN 选型理由**：
- 阿里自研推理引擎，与 Qwen 模型天然兼容，已有 `taobao-mnn/Qwen3.5-2B-MNN` 等现成模型
- 深度适配 Arm SME2 指令集，矩阵计算加速显著
- Android 核心 SO ~800KB，APK 体积影响小
- 支持 KV-cache 续写（Aura 陪伴体心跳的核心机制）

**SME2 适配思路**：
- 运行时检测 SME2 支持（`getauxval(AT_HWCAP2) & HWCAP2_SME2`）
- 有 SME2 的设备（如 MediaTek Dimensity 9500）自动启用 SME2 加速后端
- 无 SME2 的设备回退到普通 CPU / OpenCL / Vulkan 后端
- 比赛统一配发设备可确保 SME2 测试环境一致性

### 3.4 端侧适配方案

#### 3.4.1 性能策略

| 策略 | 实现 |
|---|---|
| **心跳节能** | L1 心跳 0.5 Hz，但 85% tick 为 no-op，实际生成约 0.05-0.1 Hz |
| **KV-cache 续写** | 模型状态持久化到文件，每次从上次中断处继续生成 ~30 tokens，避免每次从零开始 |
| **Dream Loop 条件触发** | 锁屏 > 5 分钟 / 充电中 / 累积消息 ≥ 10 条 / 距上次 > 6 小时 |
| **电量保护** | 电量 < 20% 不跑 Dream Loop；用户可调频率（节能/标准/高频） |
| **模型预加载** | App 启动时 `executor.preload()`，减少首次推理延迟 |
| **KV-cache 存储上限** | 单 cache 文件 ≤ 50MB，超限自动 reset；24h 自动 reset 避免偏题 |

#### 3.4.2 存储策略

```
/data/data/com.xiaoqi.companion/
├── databases/
│   └── companion.db          # Room: messages/memories/insights/mood_snapshots
├── files/
│   ├── kv_cache/
│   │   └── inner_state.bin   # KV-cache 持久化 (~50MB)
│   ├── aura_memory/
│   │   ├── MEMORY.md         # Auto Memory 索引
│   │   ├── user_patterns.md  # 用户习惯
│   │   ├── emotional_history.md
│   │   └── inner_state.md    # 内心独白日志
│   └── models/
│       └── qwen3.5-0.8b-q4.mnn  # 本地模型文件 (~0.5 GB)
```

### 3.5 Insight 生成流水线

Insight 是 Aura 的**核心差异化产品能力**，由本地 LLM 在闲时自动生成：

```
触发器（DreamLoopWorker / AnniversaryScanner / 周期触发）
    ↓
Stage 1: 数据收集（纯 SQL，不调 LLM）
    ↓
Stage 2: 本地 Qwen 归纳（maxTokens=300, temperature=0.3）
    ↓
Stage 3: Insight 提取 + 校验（必须有 evidence，confidence < 0.6 丢弃）
    ↓
Stage 4: 限流调度（同类别周上限，不在深夜推送）
    ↓
Stage 5: 呈现（主页卡片 / 聊天页 / 通知三路）
```

**三类 Insight**：

| 类型 | 频率 | 示例 |
|---|---|---|
| **Pattern**（模式识别） | 每周 ≤ 1 条 | "你过去 3 周都周日下午情绪偏低" |
| **Reminder**（重要日期） | 每周 ≤ 1 条 | "你之前提过妈妈下个月生日，要不要帮你查餐厅？" |
| **Connection**（关联发现） | 每月 ≤ 1 条 | "你上次拍夕阳和今天拍的刚好间隔两周，好像每次拍完你第二天心情都不错？" |

## 四、创新点

### 4.1 架构创新：双轨智能体（Dual-Mind）

**业界首创"云端对话体 + 本地陪伴体"的职责分离架构**。

- 不是"同一个任务的两条路径"，而是**两个不同职能的子系统**
- 云端负责"对外办事"（工具、Vision、深度思考），本地负责"对内懂事"（观察、记忆、洞察）
- 本地不是云端的"降级版"，而是拥有独立 system prompt、输入数据和输出 schema 的**独立智能体**

### 4.2 产品创新：Insight 系统 — "AI 长期认识你"

- **Insight 不是通知、不是总结、不是建议**，而是"Aura 看见了一件关于你的事，现在告诉你"
- 全部基于**本机数据**生成（messages / mood_snapshots / memories），**永远不上云**
- 每条 Insight 必须有 evidence（依据）+ confidence（信心度），可验证、可删除、可静音
- 这是云端 AI（ChatGPT / Replika / 星野）**根本性做不到的能力** —— 它们没有"在你不在时持续观察你"的本地运行时

### 4.3 技术创新：KV-cache 续写与"自我感"延续

- 陪伴体通过 MNN 的 KV-cache 持久化，实现**"自我感"的连续性**
- 今天想的是"用户最近心情不好"，明天接着这个上下文继续想，而不是每次从零开始
- 24h 自动 reset 避免偏题，50MB 上限控制存储
- 这在手机端 LLM 应用中属于**前沿探索**

### 4.4 隐私创新："数据不出手机"的护城河

- 用户对话可以上云（对话体职责），但 **mood / insight / 内在独白 / Auto Memory 永远只在本地**
- Auto Memory 文件对用户完全可见、可编辑、可删除
- 设置页直接展示 insights / mood_snapshots 条数，提供一键导出/删除
- **"比你更了解你自己、但你的隐私数据从不出本机"** —— 这是 Aura 对云端 AI 唯一不可替代的差异化

### 4.5 端云协同创新：SME2 + MNN 的性能释放

- 深度适配 Arm SME2 指令集，在手机端实现 0.8B 模型的持续低延迟推理
- 心跳 0.5 Hz + 85% no-op 策略，续航影响 < 2%/小时
- Dream Loop 条件触发 + 电量保护，让"手机算力真正释放"而不影响日常使用
